I built Code Coach with two classmates for the University of Michigan–Dearborn ACM chapter. It was our senior design project: a place to practice for programming contests and technical interviews. I designed the site and logo, and built most of the frontend and backend.

The idea was to keep the problem, code, and help in the same place. You could work through a solution, ask a question when you got stuck, and try the next idea without leaving the page.

## Coding workspace

Students could browse ICPC problems by year and region, or interview questions by category. Once you picked a problem, the statement stayed beside the editor. You could switch languages and themes, enter a test case, and run your code right there.

### Getting unstuck

The assistant received the problem and the code in your editor along with your question. That meant you could ask about the part you were working on without copying everything into a separate chat. In this example, it explains how to update a sliding window instead of adding up the same values again.

## Design and implementation

I handled the visual design, from the landing page to the coding workspace. I made the logo from two angle brackets around a dot, paired with a lowercase wordmark. The workspace is quieter than the landing page, with most of the space given to the problem and code.

<Figure
  src="/projects/codecoach/images/codecoach-landing-screen.webp"

The frontend is React, hosted on Netlify. Cognito handles sign-in, API Gateway routes requests to Node.js functions on Lambda, and MongoDB stores the users, problems, courses, discussions, and submissions. Code execution goes through Judge0. The assistant uses OpenAI through the university's UMGPT service.
