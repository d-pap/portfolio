I built SpeakLab to practice explaining technical ideas out loud. You record an explanation from memory, get feedback on the content and delivery, study the gaps, and try again.

I designed and built the app and its local AI pipeline, which runs on my own hardware.

## Explain, learn, explain again

A session starts with a technical prompt and the reference material hidden. Speaking from memory makes it easier to notice what you understand and what you struggle to explain.

SpeakLab compares the explanation with the topic's reference concepts and gives feedback on accuracy, structure, clarity, and examples. Each comment points to a passage in the transcript.

The gaps shape a short study session, with reference material and an AI tutor that can use your first attempt to answer questions. Then the notes disappear and you record again, applying what you learned.

Both attempts stay available for comparison. Review dates bring the topic back for another explanation later.

## Hearing how you communicate

SpeakLab also measures speaking rate, pauses, loudness, pitch, and filler phrases. You can replay passages to hear where a change in pace or a clearer transition could help.

I use NumPy and Praat for the audio measurements. The language model works with the transcript, references, and a summary of those measurements to suggest specific things to try in the next recording.

## Local AI pipeline

The React and TypeScript frontend records audio in the browser and sends it to a Python FastAPI backend. The server saves the recording before starting transcription, audio analysis, and model review.

whisper.cpp handles transcription, and Ollama serves the language model for assessment and tutoring. Transcription runs on the CPU to leave GPU memory for the language model. Quantized weights and a bounded context window keep the model within the available memory.

Assessments follow a JSON schema validated with Pydantic. The backend checks that cited passages exist in the transcript, gives invalid responses one repair attempt, and sends proposed factual corrections through another model review.

## Running it on a server

The app runs on a Windows PC inside WSL2. FastAPI serves the built frontend, and systemd manages the app, Ollama, and whisper.cpp as separate services. The PC holds the models and practice data; my laptop and phone run the browser.

I use SSH for remote administration and a supervised tunnel that reconnects after interruptions. Tailscale Serve provides HTTPS access from my phone, including over cellular, so microphone recording works away from my desk.

SQLite stores sessions, transcripts, feedback, tutor conversations, and review dates. Audio stays in separate files. Failed analysis can be retried from the saved recording, and reanalysis keeps earlier feedback versions for comparison.

## Ongoing work

I'm using the app to refine the topic material, interface, and feedback. Next is more individualized vocal coaching, with suggestions tied to specific moments in a recording.
